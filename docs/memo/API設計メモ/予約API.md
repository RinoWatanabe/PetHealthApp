# 予約API

## 予約一覧取得

- どの画面で使う？

予約一覧画面

- メソッドは？

GET（取得だから）

- URLは？

/api/pets/{id}/reservations

- リクエストは何が必要？

ペットID

- レスポンスは画面に何を表示したい？

予約ID
予約日
病院名
通院の目的

## 予約1件取得

- どの画面で使う？

予約登録/編集画面（編集画面）

- メソッドは？

GET（取得だから）

- URLは？

/api/reservations/{id}

- リクエストは何が必要？

なし
（予約IDはURLに含まれているから）

- レスポンスは画面に何を表示したい？

予約ID
ペットID
ペット名
予約日
病院名
通院の目的

## 予約新規登録

- どの画面で使う？

予約登録/編集画面（登録画面）

- メソッドは？

POST（登録するから）

- URLは？

/api/reservations

- リクエストは何が必要？

ペットID
予約日
病院名
通院の目的

（バックエンドが識別できる情報を渡せばいいから「ペット名」じゃなくて「ペットID」を渡す）

- レスポンスは画面に何を表示したい？

登録結果
予約ID

（一覧画面で使う情報は予約一覧取得APIを使うから、↑以外の情報必要ない）

## 予約更新

- どの画面で使う？

予約登録/編集画面（編集画面）

- メソッドは？

PUT（更新するから）

- URLは？

/api/reservations/{id}

（ペット名も変更できる仕様になるため、URLでは予約IDのみ渡す）

- リクエストは何が必要？

ペットID
予約日
病院名
通院の目的

- レスポンスは画面に何を表示したい？

更新結果
予約ID

（一覧画面で使う情報は予約一覧取得APIを使うから、↑以外の情報必要ない）

## 予約削除

- どの画面で使う？

予約登録/編集画面（編集画面）

- メソッドは？

DELETE（削除するから）

- URLは？

/api/reservations/{id}

- リクエストは何が必要？

なし（登録済みの予約を削除するだけだから。削除する予約はURLの予約IDで識別できる）

- レスポンスは画面に何を表示したい？

削除結果
予約ID

（一覧画面で使う情報は予約一覧取得APIを使うから、↑以外の情報必要ない）
