# ペットAPI

## ペット一覧取得

- どの画面で使う？

ペット一覧画面

- メソッドは？

GET（取得だから）

- URLは？

/api/pets

- リクエストは何が必要？

なし
→ 特定のペット情報がほしければリクエストにペットIDを渡す
→ 今回は登録されている全ペットの情報がほしい
→ フロントエンドに渡す条件がない
⇒ だからリクエストなしでOK

- レスポンスは画面に何を表示したい？

ペットID ★
（一覧画面上には表示しなけど必要　→ 次の処理で使うために持っておく）

ペット名
種別
種別(その他)
年齢
性別
誕生日


## ペット1件取得

- どの画面で使う？

ペット登録/編集画面（編集画面）

- メソッドは？

GET（取得するから）

- URLは？

/api/pets/{id}

※「id」で統一する（URLを見ればなんのIDか判断できるから）

- リクエストは何が必要？

ペットID（これさえ分かればペットごとの詳細取得できるはず）

- レスポンスは画面に何を表示・初期表示したい？

ペット名
ペットID
種別
種別(その他)
年齢
性別
誕生日


## ペット新規登録

- どの画面で使う？

ペット登録/編集画面（登録画面）

- メソッドは？

POST（新しく登録するから）

- URLは？

/api/pets

（特定のペットを編集するわけではなくて、新規で登録するから特にURL指定する必要はないと思うけど、理解が合っているか根拠をもって言えない）

↓

「petsという場所に、新しいペットを追加してください」というリクエストになるから、特定のIDはいらない

- リクエストは何が必要？

ペット名
種別
種別(その他)
年齢
性別
誕生日

（画面で入力した情報をバックエンドに登録してほしい）
（ペットIDはフロントから渡す情報にはないはず。バックエンドがDBに登録したときにIDが振り分けられるはず）

- レスポンスは画面に何を表示したい？

なし？（登録後に一覧画面に遷移する仕様 → バックエンドはDBに保存だけする → 一覧画面に戻ったときに一覧取得のAPIを呼べばいい？）

↓

登録結果
ペットID

（登録できたことが最低限分かる情報は返しておきたい）


## ペット更新

- どの画面で使う？

ペット登録/編集画面（編集画面）

- メソッドは？

PUT（更新だから）

- URLは？

/api/pets/{id}

(どのペットを更新するのか分かる情報としてidを入れる)

- リクエストは何が必要？

ペットID
ペット名
種別
種別（その他）
年齢
性別
誕生日

（ペットIDは、各ペットはペットIDで管理しているから、たとえペット名を変更してもどのペットを更新したのか分かるように入れる）
（あとは、更新した内容さえ分かればいいけど、仕様書にはすべて書いておく）

- レスポンスは画面に何を表示したい？

更新結果
ペットID

（ここは新規登録と考え方は同じ。更新後にペット一覧画面に戻る仕様だけど、一覧画面に戻ったときは「一覧取得」のAPIを使うからここでは結果とペットIDさえ帰ってくればいい）
